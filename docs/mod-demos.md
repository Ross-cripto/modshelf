# Local terminal demos

Every current catalog listing has a `/mods/<id>/demo` route and a bottom **Try this mod** link. These are browser-local simulations of the source behavior, not execution of downloaded mods or connection to Claude Code. User text never leaves the page. Files, agents, usage, PRs, playback, tool results and assistant replies are fixtures. Adapted game, breathing and mascot renderers are attributed in ATTRIBUTION.md. The 2026-10-12 source comparison is recorded in [core](fidelity-core.md), [hooks](fidelity-hooks.md) and [panes](fidelity-panes.md), with exact revisions, source lines, corrections and browser boundaries for all 24 listings.

## Add or update a demo

1. Confirm a real Claude Code function-hook mod and inspect its pinned hook, renderer and documented controls. Record trigger, placement, busy/idle behavior, completion, glyphs/colors and limitations.
2. Add its ID to `lib/mod-demos.ts` and an explicit definition/renderer in the appropriate `lib/demo-views/` module. Use verified source links and record the supported behavior and fixture boundaries in these docs. Keep the user-facing page concise. Initialize its default state in `createSimulation`; keep command-only surfaces closed unless the demo declares a startup command.
3. Implement state transitions and command parsing in named helpers in `lib/mod-simulation.ts`. Preserve before-tool guards, after-tool queue context, completion-only usage and independent clocks as separate mechanisms. Do not load remote code, execute commands, call a model or introduce secrets.
4. Use `DemoRow` hit targets for native controls and accessible 44px supplemental browser buttons. Images reserve explicit graphic offsets and dimensions; local graphics never hide controls. Keep user text out of terminal escape sequences.
5. Write meaningful lifecycle tests: idle, work, completion, second prompt, source-specific control and reset/cancel. Verify desktop and phone layouts and keyboard access. Run `npm test`, `npm run catalog:validate`, and `npm run build`.
6. Update this evidence matrix, retain any adapted code license, and document factual browser limits. Submit a reviewed pull request as described in CONTRIBUTING.md.

## Runtime boundaries

A visible 24-second fixture turn emits Read, Agent, Edit, check and streamed reply stages. Each adapter consumes only its appropriate events. Pause progression while the page is hidden; dispose timers, observers, listeners and the terminal on navigation. Stop prevents pending tools and completion. Reset restores local state. The queue has an eight-entry browser cap and the transcript retains forty entries; these limits are explicitly smaller than some native plugins. Native settings outside the listed controls are not emulated.
